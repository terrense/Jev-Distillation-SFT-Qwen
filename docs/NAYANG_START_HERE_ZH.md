# Nayang，先从这里接手

你接手的是医院智能体的“入口分流”环节。模型只要读懂用户当前想做什么，再交给对应模块。它不负责诊断疾病，也不应该在这一层写长篇医疗回答。

## 先用四句话理解目标

| 用户说什么 | 应去哪里 |
|---|---|
| 头晕应该挂哪个科？ | triage：导诊，选择科室 |
| 号挂好了，先帮我把病情说清楚 | preconsult：见医生前收集病史 |
| 我挂好号了，厕所在哪？停车费怎么交？ | info：医院位置与行政流程 |
| 帮我写诗/做编程作业 | other：范围外，固定说明或拒答 |

最容易错的是“同一句话、不同上下文”。例如“三天了”：如果上一句问症状持续多久，就是导诊/预问诊的补充；如果问车停多久，就是停车咨询；没有前文就先澄清。不能把听不懂都叫other。

四类标签和下一步行为是两件事：`ROUTE`表示交给对应模块，`CLARIFY`表示先问清，`ESCALATE`表示按独立规则转专业人员。危险情况不会因为模型自信地判成info就自动变安全。

## 蒸馏在这里是什么意思

你可以把它理解成：更强的教师先给一批输入做判断，再用经过审核的例子教小模型。

生成式模型/人工负责写候选场景；Jev只做分类判断，不能替你生成几万条用户话语。Jev还会给出四类概率，接近时通常值得复核。但教师会错，两位教师一致也不等于人类金标。

第一阶段先做“输入→正确标签”的硬标签SFT即可。完整四类概率经过核验和校准，才考虑软标签；教师解释不等于真实logits，挑学生难例再请教师标注也不等于token级OPD。先用可证明有用的简单方法，再增加复杂度。

## 你今天可以完成的第一件事

1. 按README安装CPU准备依赖并运行检查，不需要显卡或Jev密钥。
2. 独立填写`实验准备/data/annotation_nayang.v1.jsonl`。把`annotation_you.v1.jsonl`交给另一位人类独立标注者；“you”只是历史文件名，不必由原项目用户本人填写。
3. 先别看候选和教师答案，避免被带偏。两人都标完后，让agent运行`merge_annotations.py`，把分歧拿出来讨论。
4. 再补44条两人各自编写的新场景，形成首轮200条试标。先定清边界再扩量，效率比先造几万条更高。

agent可以帮你检查格式、解释概念、整理分歧和跑脚本；它不能假装第二位人类，也不能替专业人员审批医疗升级规则。

## 后面怎么推进

第一轮先做4,000条训练、500条开发、1,000条独立测试的MVP。工程目标仍为20,000训练/2,000开发/3,000测试。论文计划采用另一套6,000人工金标划分，两者不要累加成重复造数据的任务；细节见`实验准备/TASK_MATRIX.md`。

你现在是负责人，可以把旧任务表中原本分给“你”的工程工作交给自己的agent。你本人重点做范围决定、质量判断、协调第二标注者与专业复核；让agent维护来源、去重、预算、版本和报告。

先比较原prompt、精简prompt、中文encoder/TF-IDF和未微调学生，再判断SFT是否值得。以后若8B没赢过小分类器，这也是有价值的结果，不需要为了论文把它写成赢了。

## Jev怎么接着用

仓库的密钥入口见`CREDENTIALS.md`。优先用GitHub Actions的手动小批次任务，普通测试不会花点数。每次任务有显式请求上限，结果下载后先复核再入库。

如果你要在本机直接调API，需要通过环境变量配置你自己的有效密钥；GitHub Secret不能被读回。你只负责撤销/更换密钥，不需要把它写进脚本。原用户计划近期作废旧key，因此先确认可用性，不依赖它一直有效。

## 暂时不能被agent自动补出来的东西

真实人工金标、实际外院/时间外测数据、经过专业审核的升级规则，以及正式模型训练效果，都需要真实工作。不要用假医院名、合成日期或模型自标去冒充。

更详细的缺口在`实验准备/GAP_AUDIT.md`，执行命令在`实验准备/RUNBOOK.md`。历史C:/F:路径是原机器上的证据位置；在你机器上使用仓库相对路径。
