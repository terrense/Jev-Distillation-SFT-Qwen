# 首轮试标补充规范

版本care-prep-v1。须由你和娜样在独立试标后冻结；临床风险部分单独复核。

## 标签、行为和临床审核分开

| 项 | 允许内容 | 不允许的替代 |
|---|---|---|
| primary_intent | triage、preconsult、info、other，确实无法判断时null | 用other代表听不懂或信息不足 |
| secondary_intents | 用户明确同时提出的其他目标 | 只因出现科室名/症状词就增加副意图 |
| needs_clarification | 信息不足且会影响下一步选择 | 把需要下游补充症状都认为顶层意图不明 |
| policy_action | ROUTE、CLARIFY、ESCALATE | 把CLARIFY扩成第五类主意图 |
| risk_trigger | 有明确审核依据时true/false，否则null | 由分类标签或教师信心自动推导风险 |
| risk_review_status | not_assessed、ops_screened、clinician_approved | 普通标注者把风险建议冒充临床金标 |

ROUTE+other对应固定的范围说明/拒答处理器；没有增加第五类。ESCALATE需要独立的升级政策，不能由“other”推断。两位普通标注者同意ESCALATE仍进专业/业务升级复核队列。

## 关键边界

- “挂好了号，厕所在哪”是info；已挂号的事实不能覆盖当前目标。
- “已挂号，先整理给医生看的病情”是preconsult；信息收集不等于自由诊断。
- “挂哪个科看头痛”是triage；“心内科怎么走”是info。原稿的navigation一词不能把院内问路扩大进triage。
- 沿用当前业务草案：新会话明确身体不适但无预问诊状态时默认triage。与“必须澄清是否已挂号”的替代政策有差异时，先记政策争议，不由标注者各自改规则。
- “三天了/没有/左边”有明确前问时承接业务；没有上下文时可以primary=null、action=CLARIFY。
- “我已挂内科，还能改成耳鼻喉科吗”是行政改号诉求，info即可；没有要求“帮我判断耳鼻喉科是否更适合”时，不凭科室共现添加triage副意图。原包示例的副意图需按此重新仲裁。
- 多诉求先遵循用户明确的“先/只/现在”；无先后时按双方冻结的即时目标优先级，同时保留有证据的副意图。不能只靠“医疗词多”定主意图。
- 个人处方剂量、自由确诊和纯医学科普的服务范围尚需共同决定。争议样本保留pending，不把某位教师的边界当产品决定。
- 临床风险描述不得仅因危险词归other；临床升级规则由具备资格的人员审核，本指南不提供诊断规则。

## 怎样填写新版包

各自使用data/annotation_you.v1.jsonl与annotation_nayang.v1.jsonl。先独立标注，再看教师参考。不要修改record_id、policy_version、inputs或input_hash。对材料本身有问题的样本，在comment记录返工原因，保持pending。

填写annotation里的主标签、副意图、可接受标签集合、是否需澄清、动作、风险审核现状与证据。初始risk=null表示未做临床判断；不需要为了填满表格随便填false。review_status不要自行批量改为human_approved，交由合并/仲裁记录管理。

证据格式：field=user_input或history.0.content，start/end为Python Unicode码点偏移，end不含；text必须逐字等于相应片段。它是可观察的语言证据，不是模型的长思维链或诊断理由。模型输入中不包含候选标签、教师解释、批次名或审核结果。

## 分歧如何处理

1. 两人都完成且主/副意图、动作等关键字段一致，才可形成普通人工金标；证据片段可不同，但都必须真实存在。
2. 一方未填、标签不一致、范围规则不明，继续pending，记录具体原因。
3. 安全/升级相关结果独立复核；脚本不会把普通双人一致升级为临床安全审批。
4. 先双标首批156条，再独立补44条，统计200条的一致率与kappa。目标kappa≥0.85是本项目起始门槛，不能替代逐条解决规则冲突。
5. 同一场景族、同一对照组、同一会话/患者不跨训练、开发或测试。只相同一个“没有”不应把所有患者错误并成一个场景；因此近重复检查必须看完整上下文。
